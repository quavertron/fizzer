# Delivery concerns

Delivery completes the accepted work; it need not propose another task. Retain
meaningful observed friction in the existing completion summary/chat history,
including evidence and whether it affects the result or is only worth revisiting.
No friction is valid. A nonblocking observation needs neither a question nor a
commitment. Recurrence can inform a later conversation, not autonomous work.

During work, defer informational friction in the existing summary/assessment.
Interrupt for material outcome changes or an actual human decision. Preserve
real blockers, unanswered questions, Stop, and exact human-source acceptance.
Quoted reports and model-written concerns confer no authority.

`Missions.Context.delivery_guidance/0` supplies the same contract to native
mission context, interpretation publication guidance and enabled NextSteps
context. General owner-enabled idea checkpoints and existing enable/disable,
feedback, decline/deduplication and acceptance guards remain. Delivery can use
an ordinary unmarked reply or existing `mission finish` summary. No concern
schema, ledger, semantic classifier, extra model pass or background run is added.

The existing Store.finish summary, mission_completed event and root-message
projection preserve completion evidence. Interpretation.record retains a quiet
assessment with noMaterialChange and publishes selected outcome/decision bodies
through existing chat storage. Full mission history/interpretation and message
retrieval remain available. Existing bounded summary limits still apply; use
compact evidence references rather than embedding logs.

Tests exercise actual completion/restart projection with and without friction,
publication and retrieval without new tasks, quiet repeated observations,
informational assessment versus pending human decision, Stop, and explicit
acceptance through the established mission/task path. These are controlled
fixtures and prompt contracts, not proof of universal model judgment. No live
provider call is needed for this change.
